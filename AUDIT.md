## 1. Архитектура (как есть на входе)

Монолит на Go + React Mini App, один бинарник отдаёт и API, и статику фронта,
и обслуживает Telegram-бота.

```
cmd/main.go            — точка входа: gorm.Open → AutoMigrate → storage → repo → service → API + Bot
internal/model/        — GORM-модели + конечный автомат статусов заказа
internal/repository/   — SQL-доступ (GORM), in-memory кэш витрины, нечёткий поиск
internal/service/      — CreateOrder / TransitionOrder / ApplyDeepLinkPromo
internal/handler/      — api.go (HTTP), bot.go (Telegram), initdata.go (HMAC), webhook.go
internal/storage/      — Storage-интерфейс: Local (диск) | Postgres (bytea) + ресайз фото
migrations/            — «справочный SQL», схему на самом деле применяет AutoMigrate
web/                   — React 18 + Vite + Tailwind, SPA на react-router
```

**Точки входа**

1. HTTP `:$PORT` → `API.Routes()` (net/http ServeMux, Go 1.22 patterns).
2. Telegram-апдейты: long polling (`bot.Run()`) **или** webhook (`POST /telegram/<secret>`).

**Поток заказа**

`Checkout.tsx` → `POST /api/orders` (+ header `X-Telegram-Init-Data`) →
`telegramUserID()` (HMAC-SHA256 по токену бота) → `service.CreateOrder` →
валидация → пересчёт суммы по ценам из БД → промокод → `repo.CreateOrder` →
`go NotifyNewOrder` → карточка заказа всем админам в Telegram.

**Поток бота**

`Run()`/`WebhookHandler` → `handleMessage` (визарды `/add`, `/edit`, `/fresh`,
`/clients`) либо `handleCallback` (`cat`, `addok`, `edit`, `editf`, `hide`,
`del`, `pg`, `o:<id>:next|cancel`, `cl`, `flt`, `x`, `clean`, `ophoto`).

**Внешние интеграции:** только Telegram Bot API. Оплаты нет — приём заказа,
подтверждение вручную.

## 2. Бизнес-правила (как реализовано на входе)

- Товар = `Product` + N `ProductVariant` (кол-во цветов → цена, целые рубли) + до 5 фото.
- Витрина отдаёт только `is_hidden = false AND archived_at IS NULL`; варианты — `archived_at IS NULL`, отсортированы по цене; карточка показывает минимальную цену.
- Удаление товара — soft delete (`archived_at`), потому что `order_items.variant_id` ссылается на `product_variants`.
- Правка цен — архивирование старых вариантов + вставка новых (старые физически удаляются, если ни в одном заказе).
- Сумма заказа считается **только на сервере** по ценам из БД; клиентские цены игнорируются.
- Промокод: процент от итога, округление вниз. Явно введённый приоритетнее сохранённого по deep-link `t.me/<bot>?start=CODE`.
- Статусы: `new → confirmed → assembling → photo_sent → delivering → delivered`, отмена из любого нетерминального. Переходы — только на следующий шаг.
- Уведомления клиенту при `confirmed / assembling / delivering / delivered / cancelled`.
- Доставка: «в течение часа» или «к HH:MM» в окне 9:00–21:00.
