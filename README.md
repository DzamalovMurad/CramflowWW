# Flowix — цветочный магазин в Telegram 🌸

Mini App для заказа букетов с доставкой по Москве плюс админ-бот в том же
чате Telegram. Онлайн-оплаты нет: заказ принимается, подтверждается и
сопровождается вручную, клиент получает уведомления от бота.

Один Go-бинарник обслуживает всё: HTTP API, статику Mini App, Telegram-бота
и фоновые задания.

## Стек и структура

- **Backend:** Go 1.25, PostgreSQL (GORM для запросов, собственный раннер миграций)
- **Bot:** `go-telegram-bot-api/v5`, режим webhook
- **Frontend:** React 18 + TypeScript + Tailwind + Vite, Telegram WebApp SDK
- **Хостинг:** Railway (`railway.toml` + `Dockerfile` — единственный источник правды)

```
cmd/                  — точка входа, сборка зависимостей, graceful shutdown, сидинг
internal/config/      — всё чтение окружения ровно в одном месте
internal/migrate/     — раннер SQL-миграций (advisory lock, транзакция на файл)
internal/model/       — сущности, конечный автомат статусов, арифметика денег
internal/repository/  — доступ к БД, кэш витрины, нечёткий поиск
internal/service/     — приём заказа: валидация, цены, промокоды, остатки
internal/handler/     — HTTP API, middleware, Telegram-бот, webhook, initData
internal/storage/     — хранилище фото: Postgres (по умолчанию) или диск
internal/backup/      — ежедневный pg_dump в Telegram админам
internal/testdb/      — обвязка интеграционных тестов
migrations/           — SQL-миграции, вшитые в бинарник (//go:embed)
web/                  — Mini App
```

## Как это работает

**Заказ.** Mini App → `POST /api/orders` с заголовками `X-Telegram-Init-Data`
(подпись Telegram) и `Idempotency-Key`. Сервер проверяет подпись, валидирует
поля, **в одной транзакции** считает сумму по ценам из БД, списывает остатки,
применяет промокод и сохраняет заказ. После коммита карточка заказа уходит
администраторам в Telegram.

**Статусы.** `new → confirmed → assembling → delivering → delivered`, отмена
возможна из любого нестатусного финала. Переход разрешён только на следующий
шаг. Клиенту на каждом шаге приходит сообщение от бота. Отмена возвращает
остатки на склад.

**Фото букета** отправляется клиенту отдельным действием и статус не меняет.

## Переменные окружения

Полный список того, что читает код. Пример со значениями — в `.env.example`.

### Обязательные

| Переменная | Назначение | Если не задать |
|---|---|---|
| `DATABASE_URL` | подключение к PostgreSQL | сервис не стартует |
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather | бот не запускается, **и заказы оформить нельзя**: подпись initData проверяется этим токеном |
| `TELEGRAM_ADMIN_IDS` | telegram_id админов через запятую | заказы некому получать, команды бота недоступны, бэкапы не отправляются |

### Настраиваемые

| Переменная | По умолчанию | Назначение | Если не задать |
|---|---|---|---|
| `PUBLIC_URL` | из `RAILWAY_PUBLIC_DOMAIN` | публичный https-адрес: Mini App, webhook, кнопка меню | на Railway подставится сам; иначе бот уйдёт в long polling, кнопка меню не настроится |
| `TELEGRAM_WEBHOOK_SECRET` | генерируется | секрет пути и заголовка `X-Telegram-Bot-Api-Secret-Token` | сгенерируется временный: после каждого рестарта webhook перерегистрируется |
| `BOT_MODE` | `webhook` | `webhook` или `polling` | webhook; без `PUBLIC_URL` автоматически откатится в polling |
| `UPLOAD_STORE` | `db` | где хранить фото товаров: `db` или `local` | фото в БД — переживают редеплой без Volume. Ставьте `local`, только если к сервису **подключён Volume** на `/app/uploads`: тогда фото лежат файлами на нём |
| `UPLOAD_DIR` | `./uploads` | папка для фото при `UPLOAD_STORE=local` | `./uploads`; **без Railway Volume фото пропадут при редеплое** |
| `WELCOME_PHOTO` | — | фото первого экрана бота: `file_id` или прямая https-ссылка | приветствие уходит текстом с той же кнопкой — путь до каталога не ломается |
| `WEB_DIST` | `./web/dist` | собранный фронтенд | в Docker-образе выставлен автоматически |
| `PORT` | `8080` | порт HTTP-сервера | Railway подставляет свой |
| `APP_TIMEZONE` | `Europe/Moscow` | часовой пояс магазина | Москва; от него зависят даты доставки и «сегодня на базе» |
| `SHOP_OPEN_HOUR` | `9` | час начала приёма доставки | 9:00 |
| `SHOP_CLOSE_HOUR` | `21` | час окончания | 21:00 |
| `BACKUP_ENABLED` | `true` | ежедневный дамп БД в Telegram | включено, если есть бот и админы |
| `BACKUP_HOUR` | `4` | час снятия дампа (время магазина) | 04:00 |

## Шаг 1. Бот в BotFather

1. [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username.
   Полученный токен — это `TELEGRAM_BOT_TOKEN`. **Никуда его не коммитьте.**
2. `/setcommands` → выберите бота → вставьте целиком:

   ```
   start - Открыть каталог
   orders - Заказы по статусам
   today - Доставки на сегодня
   preorders - Предзаказы на будущие даты
   clients - Найти клиента по имени или телефону
   add - Добавить товар
   edit - Изменить товар
   hide - Скрыть или показать товар
   delete - Удалить товар
   promo - Промокоды: список и вкл/выкл
   promoadd - Создать промокод
   fresh - Что сегодня свежее на базе
   clean - Очистить историю чата
   cancel - Прервать текущее действие
   help - Список команд
   ```

   Тот же список бот выставляет себе сам при старте, так что шаг
   подстраховочный — но полезный, если бот ещё не запускался.
3. Узнайте свой telegram_id через [@userinfobot](https://t.me/userinfobot) —
   это `TELEGRAM_ADMIN_IDS`. Несколько админов — через запятую.

## Шаг 2. Деплой на Railway

1. [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo**
   → выберите этот репозиторий. Сборка идёт по `Dockerfile`.
2. **+ New → Database → PostgreSQL**.
3. Сервис приложения → **Variables**:
   - `DATABASE_URL` = `${{Postgres.DATABASE_URL}}` (reference на сервис БД)
   - `TELEGRAM_BOT_TOKEN` — из шага 1
   - `TELEGRAM_ADMIN_IDS` — из шага 1
   - `TELEGRAM_WEBHOOK_SECRET` — любая длинная случайная строка
     (`openssl rand -hex 24`)
4. **Settings → Networking → Generate Domain**. `PUBLIC_URL` задавать не нужно:
   сервис берёт домен из `RAILWAY_PUBLIC_DOMAIN` автоматически.
   Если к сервису подключён Volume на `/app/uploads` и на нём уже лежат фото
   товаров — добавьте `UPLOAD_STORE=local`, иначе старые фото не найдутся.
5. Дождитесь деплоя. Healthcheck `/api/health` должен стать зелёным — он
   проверяет реальное соединение с БД, а не просто отвечает «ok».

Схема БД применяется автоматически при старте: миграции из `migrations/`
вшиты в бинарник и выполняются ровно один раз.

### Наполнить витрину демо-товарами (необязательно)

Если хотите не пустой каталог на старте:

```bash
railway run ./flowix -seed
```

Добавит 7 букетов с фото и промокод `WELCOME10` (−10%, один раз на клиента).
Повторный запуск ничего не дублирует. Свои товары заводятся через `/add`.

## Шаг 3. Привязка Mini App

Кнопку меню бот настраивает себе сам при старте — она ведёт на `PUBLIC_URL`
(в логах строка «кнопка меню бота ведёт на Mini App»). Проверить можно в
@BotFather: **Bot Settings → Menu Button**.

Если Mini App почему-то не открывается, в @BotFather выполните
`/setdomain` → выберите бота → отправьте домен без схемы
(`xxx.up.railway.app`).

Deep-link с промокодом: `https://t.me/<username_бота>?start=WELCOME10` —
код закрепляется за клиентом и применяется при оформлении автоматически.

## Команды админ-бота

Работают только для `TELEGRAM_ADMIN_IDS` — и в личном сообщении, и в
callback-кнопках. Остальным бот показывает приветствие и кнопку «Открыть каталог».

| Команда | Что делает |
|---|---|
| `/orders` | заказы по статусам со счётчиками, постранично, карточка в один тап |
| `/today` | что везём сегодня, по времени доставки, с общей суммой |
| `/preorders` | активные заказы на будущие даты |
| `/clients <запрос>` | поиск клиента по имени или телефону: LTV, средний чек, последние заказы |
| `/add` | визард: название → 4–5 фото файлом → описание → варианты и цены → категория |
| `/edit` | название, описание, цены, категория, фото, бейдж «ХИТ», скидка, остаток, скрыть/показать |
| `/hide`, `/delete` | скрыть или убрать товар из каталога (история заказов сохраняется) |
| `/promo` | список промокодов: правило скидки, порог, остаток лимита, кнопка вкл/выкл |
| `/promoadd` | визард: код → скидка → минимальная сумма → срок → лимиты |
| `/fresh <список>` | «Сегодня на базе» — блок на главной Mini App |
| `/clean` | удалить историю переписки с ботом |
| `/cancel` | прервать текущий визард |

## Первый экран клиента

`/start` для не-админа — одно сообщение и одна кнопка **🌸 Открыть каталог**,
открывающая Mini App. Никаких развилок: всё, что не ведёт в каталог, с этого
экрана убрано. Ссылка с промокодом (`?start=КОД`) показывает тот же экран,
только с приписанным подарком; если код протух, клиент просто видит обычное
приветствие — извиняться за испорченную ссылку не за что.

Фото задаётся переменной `WELCOME_PHOTO` — `file_id` или прямая https-ссылка
(подойдёт и адрес фото товара с этого же сервиса, например
`https://<домен>/uploads/<файл>.jpg`). Если фото не задано или Telegram его не
принял, уходит тот же текст сообщением — кнопка на месте в обоих случаях.

Что нужно от снимка: один букет крупным планом, естественный дневной свет,
светлый спокойный фон, вертикальный кадр 3:4, крафтовая упаковка с фирменной
надписью в кадре. Без коллажей, водяных знаков, текста поверх фото и витрины
целиком — на первом экране продаёт один букет, а не ассортимент.

В карточке заказа: **➡️ следующий статус**, **📷 фото букета** (уходит клиенту
без пересжатия), **❌ отменить** (причина обязательна, остатки возвращаются).

**Фото товаров присылайте файлом**, не «фото»: Telegram сжимает картинки до
~1280px, и на витрине это заметно. Сервер сам уменьшит снимок до 2000px
и переведёт в JPEG.

**Остаток товара.** По умолчанию не ведётся. Если задать число через
`/edit → 📦 Остаток`, оно уменьшается при каждом заказе, возвращается при
отмене, при ≤5 на витрине появляется бейдж «осталось N», при 0 букет нельзя
заказать. Снять учёт — прислать `-`.

## Промокоды

Заводятся из бота: `/promoadd` — пять шагов, каждый проверяется сразу.
`/promo` показывает список и переключает коды кнопкой.

Что умеет один код:

| Поле | Значение |
|---|---|
| `code` | уникальный, регистр не важен; латиница, цифры, `-` и `_` — код живёт в deep-link `?start=CODE` |
| `discount_type` | `percent` (процент от суммы) или `fixed` (рубли) |
| `discount_value` | 1–90 для процента, 1–1 000 000 ₽ для фиксированной скидки |
| `min_order_amount` | минимальная сумма заказа **до скидки**; 0 — без ограничения |
| `max_uses` | сколько всего раз можно применить; 0 — без ограничения |
| `per_user_limit` | сколько раз одному клиенту; 0 — без ограничения, по умолчанию 1 |
| `is_active` | вкл/выкл без удаления |
| `expires_at` | срок действия; в боте вводится как «до 31.12.2026» включительно |

То же самое можно сделать напрямую в БД:

```sql
-- 20% всем, но не больше 100 применений и по одному разу на клиента
INSERT INTO promo_codes (code, discount_type, discount_value, max_uses, per_user_limit)
VALUES ('SPRING20', 'percent', 20, 100, 1);

-- 500 ₽ на заказ от 3000 ₽
INSERT INTO promo_codes (code, discount_type, discount_value, min_order_amount)
VALUES ('MINUS500', 'fixed', 500, 3000);

-- отключить код
UPDATE promo_codes SET is_active = FALSE WHERE code = 'SPRING20';
```

Скидку считает только сервер, по ценам из БД: сумма, присланная клиентом,
игнорируется. Скидка в целых рублях с округлением вниз и никогда не больше
суммы заказа. Все проверки и списание идут в той же транзакции, что и заказ,
под блокировкой строки промокода (`SELECT … FOR UPDATE`) — одновременные
заказы не пробьют ни общий лимит, ни лимит на клиента. Применённый код
дублируется в самом заказе (`orders.applied_promo_code`), поэтому история
остаётся читаемой даже после удаления акции.

Ограничение: в корзине Mini App предварительно показывается только процентная
скидка. Фиксированная применяется при оформлении и видна в готовом заказе,
но предпросмотр её пока не рисует.

## Резервные копии и восстановление

Каждую ночь в `BACKUP_HOUR` (по умолчанию 04:00 МСК) сервис снимает `pg_dump`
в формате custom и присылает файл `flowix-YYYY-MM-DD_HH-MM.dump` всем
администраторам в Telegram. Отдельная инфраструктура не нужна — копия лежит
в личном чате владельца.

Проверить прямо сейчас, не дожидаясь ночи:

```bash
railway run ./flowix -backup
```

### Восстановление

Процедура проверена автотестом (`internal/backup`): дамп снимается,
восстанавливается в **чистую** базу, и приложение поднимается поверх неё
без ручных доделок.

1. Скачайте `.dump` из чата с ботом.
2. Создайте новую пустую базу (в Railway: **+ New → Database → PostgreSQL**).
3. Восстановите:

   ```bash
   pg_restore --dbname "$NEW_DATABASE_URL" --no-owner --no-privileges flowix-2026-08-01_04-00.dump
   ```

4. Переключите `DATABASE_URL` сервиса на новую базу и передеплойте.

Восстанавливать нужно именно в пустую базу: `pg_restore` в живую упрётся в
уже существующие таблицы.

## Локальная разработка

```bash
# 1. PostgreSQL
docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=dev -e POSTGRES_DB=flowix postgres:16

# 2. Окружение
cp .env.example .env    # .env в .gitignore
export $(grep -v '^#' .env | xargs)

# 3. Backend (миграции применятся сами)
go run ./cmd -seed      # один раз, демо-каталог
go run ./cmd

# 4. Frontend в dev-режиме (:5173, /api проксируется на :8080)
cd web && npm install && npm run dev
```

Без `TELEGRAM_BOT_TOKEN` сервис поднимется как чистый API: каталог виден,
но оформить заказ нельзя — подпись Telegram проверить нечем.

Продакшен-сборка фронта (Go-сервер отдаёт `web/dist` сам):

```bash
cd web && npm run build
```

Интеграционные тесты покрывают то, что стоит денег: суммы и скидки,

применение миграций к пустой базе и цикл бэкап → восстановление.

| Что меняем | Где |

## Принятые решения

- **Заказ только из Telegram.** Оформление требует валидной `initData`.
  Раньше запросы без подписи привязывались к общему «гостю» — из-за этого
  перебором id из браузера читались чужие имя, телефон и адрес.
- **Идемпотентность заказа** — по заголовку `Idempotency-Key` и уникальному
  индексу в БД: двойной тап и ретрай после обрыва сети не создают второй заказ.
- **Деньги — только целые рубли**, считаются на сервере по ценам из БД;
  `total = subtotal − discount`, скидка округляется вниз.
- **Один механизм миграций** — SQL-файлы из `migrations/`. GORM AutoMigrate
  не используется.
- **Фото товаров по умолчанию в Postgres**: на Railway без подключённого
  Volume файлы на диске исчезают при каждом редеплое.
- **`file_id` Telegram нигде не сохраняются** — фото букета пересылается
  клиенту сразу после загрузки, поэтому смена бота ничего не ломает.
- **Часовой пояс магазина явный** (`Europe/Moscow`): контейнер живёт в UTC,
  и без этого после 21:00 сервер считал бы, что «сегодня» — вчера.
- **Одна реплика.** В приложении есть in-memory кэш витрины и состояние
  визардов бота; горизонтальное масштабирование потребует вынести их наружу.
- **Отправка фото букета не двигает статус**: это событие, а не шаг конвейера.
  Раньше статус `photo_sent` приходилось «проходить» даже без фото.
- **Получатель отдельно от заказчика**: курьер звонит тому, кто откроет дверь,
  иначе сюрприз испорчен, а доставка срывается.
