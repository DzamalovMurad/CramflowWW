## Известные ограничения

Осознанные решения, а не забытые задачи.

1. **Одна реплика.** Кэш витрины и состояние визардов бота живут в памяти
   процесса. При двух репликах правки админа расходились бы до минуты, а
   визард `/add` ломался бы на середине. Для нагрузки цветочного магазина
   одной реплики достаточно с большим запасом; масштабирование потребует
   вынести кэш и состояние в Redis.

2. **Rate limiter в памяти.** По той же причине: лимиты считаются на инстанс.
   Для одной реплики это ровно то, что нужно.

3. **Бэкап уезжает в Telegram, а не в объектное хранилище.** Ограничение —
   45 МБ на файл: при нынешних объёмах (дамп годовой базы — единицы мегабайт)
   запас многолетний, но при кратном росте фото в БД понадобится S3.
   Сервис сообщит об этом в лог явной ошибкой, а не молча перестанет
   делать копии.

4. **Ёмкость слотов доставки не ограничивается.** Магазин может принять
   20 заказов «в течение часа» на один час. Автоматический лимит требует
   знания реальной пропускной способности курьеров, которой в системе нет;
   вводить цифру наугад — хуже, чем не вводить. Админ видит нагрузку через
   `/today` и может закрыть приём, скрыв товары.

5. **Поиск клиентов — последовательный скан.** 14 мс на 8 000 клиентов;
   команда админская и редкая. Ускорение потребует расширения `pg_trgm` —
   заводить его ради этого не стоит.

6. **Онлайн-оплаты нет.** Как и было задумано: заказ подтверждается вручную.

7. **Порядок «популярного» обновляется раз в 5 минут.** Пересчёт на каждый
   запрос стоил 52 мс; для витрины такая точность не нужна.

8. **На `react-router-dom` 7.18.2 остаётся один advisory** —
   [GHSA-qwww-vcr4-c8h2](https://github.com/advisories/GHSA-qwww-vcr4-c8h2),
   «RSC Mode CSRF Bypass». Он относится к режиму React Server Components:
   к `createBrowserRouter`, `loader`/`action`, `useFetcher` и `<Form>`.
   Проект использует только `BrowserRouter` + `Routes`/`Link`/`useNavigate`,
   ничего из перечисленного нет (проверено `grep` по `src/`), поэтому
   поверхность недостижима. Единственная версия без него — 7.11.0, но она
   возвращает open redirect → XSS в `<Link>` и `useNavigate`, то есть ровно
   в тех API, которыми мы пользуемся. Выбрана 7.18.2 как строго менее
   рискованная. Обновиться, когда выйдет версия без обоих.

9. **Образ Docker целиком не собирался.** В окружении разработки нет демона
   Docker. Каждый шаг `Dockerfile` проверен по отдельности: `npm ci` проходит
   по lock-файлу, Go-сборка с продакшен-флагами даёт рабочий бинарник,
   пакет `postgresql16-client` (16.14-r0) в Alpine 3.21 существует, а
   миграции действительно вшиты в бинарник — он применяет их, запущенный
   из пустого каталога. Первая сборка на Railway остаётся первой настоящей
   проверкой связки целиком.

10. **Telegram-бот не проверялся против живого API.** Токен доступен только
   в рантайме, в этом окружении внешние вызовы к `api.telegram.org` не
   выполнялись. Логика бота покрыта тестами на уровне БД и маршрутизации,
   но первый запуск с настоящим ботом нужно проверить вручную по чек-листу
   из отчёта: `/start`, `/add`, оформление заказа, смена статуса.
